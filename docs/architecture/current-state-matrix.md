# Patchwork current-state matrix

Updated: 2026-07-28

This is the authoritative description of what the Patchwork runtime does today. It distinguishes tested contracts and in-memory models from durable or externally integrated behavior. The continuation sequence and exit gates live in `docs/superpowers/plans/2026-07-10-patchwork-continuation-roadmap.md`.

## Maturity labels

| Label | Meaning |
| --- | --- |
| `contract-only` | Types, validators, domain rules, fixtures, or tests exist, but there is no complete runtime path. |
| `fixture-runtime` | A runnable path exists, but its primary state or external behavior is simulated or process-local. |
| `partially-persistent` | A runnable path uses durable storage for part of its behavior, while material state or integration remains simulated or volatile. |
| `externally-integrated` | The runtime talks to its intended external system and has integration coverage, but production operations have not been demonstrated. |
| `production-ready` | External integration, durability, security, deployment, recovery, monitoring, and operational ownership are all demonstrated. |

No subsystem is currently `production-ready`.

## Confirmed reusable assets

- The five lexicons, their validators, and valid/invalid fixtures.
- Deterministic normalization, tombstone, discovery, ranking, privacy-redaction, and authorization domain logic.
- The PostgreSQL discovery-event slice and migration harness as starting patterns, not a complete schema.
- React design-system primitives, route shell, settings and discovery UX, accessibility helpers, and localization framework.
- The unit and contract test corpus as an executable specification, provided test names are not treated as proof of external integration.
- Docker build stages, configuration validation, metrics formats, and operational runbooks as scaffolding to be verified against a real staging system.

## Data-loss boundaries

A process restart preserves OAuth/session state, lifecycle state and audit, blocks, reports, moderation queues and audit, HTTP idempotency responses, public-sync state, account export/deactivation state, durable aid-post and directory-resource projections, deletion tombstones, dead letters, and the live indexer cursor when their PostgreSQL runtimes are configured. It still loses the older in-process index and all material state in fixture-only expansion subsystems such as chat, settings preferences, volunteer, verification, attachments, inbox, scheduling, groups, organizations, reputation, matching, tenants, and connectors.

## Verification interpretation

The repository unit/contract gate passes 897 tests. The retained suite includes local WebSocket ingestion, durable projection CIDs, session-derived block filtering, authenticated private lifecycle reads and public-sync recovery, automatic lifecycle reconciliation, authenticated account export/deactivation, PostgreSQL, authenticated safety HTTP, cookie-only authentication, API and moderation retention, unique production contract advertising, production data-mode enforcement, deployment/digest contracts, browser-adjacent coverage, metrics-series integrity, the bounded HTTP load probe, and fail-closed staging-capacity evidence evaluation. Fifty-six local Chromium cases pass, the externally gated two-account case passed after the prior digest deployment, and nine direct service-integration cases pass separately. Passing controlled home-network tests still does not substitute for protected promotion, independent durability, human ownership, and production operations.
